# 院内処方 在庫・発送管理 — 導入手順書

在庫アプリ（ワクチン用）とは **完全に別のURL・別のFirebase・別のGitHubリポジトリ** で作ります。既存の本番には一切触りません。

## 0. 全体像

| 部品 | 役割 |
|---|---|
| GitHub（新規リポジトリ） | コードの置き場 |
| Vercel（新規プロジェクト） | Webで公開（GitHubに push すると自動で更新） |
| Firebase Realtime Database（新規プロジェクト） | 在庫データの保存場所（全端末で共有） |
| 入稿用Excel（`public/template.xlsx`） | 薬剤マスタ・在庫・発送プランの初期データ |

画面は3つです。
- **発送**：プラン名を選ぶ → 詰めるものと個数が出る → 発送先・配送番号を書いて「出庫を記録する」
- **在庫**：発注が必要な薬剤の一覧／発注済／入荷／入庫・出庫の記録と履歴
- **設定**：Excel取り込み、バックアップ書き出し

---

## 1. Firebase（新規プロジェクト）

1. https://console.firebase.google.com で「プロジェクトを追加」。名前は何でもよい（例：`clinic-stock`）。Googleアナリティクスは無効でよい。
2. 左メニュー「構築」→「Realtime Database」→「データベースを作成」。
   - ロケーション：`asia-southeast1`（シンガポール）を選ぶ。
   - 「ロックモードで開始」を選ぶ。
3. 「ルール」タブを開き、中身を **すべて消して** 次を貼り付け、「公開」を押す。

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "$room": {
      ".read": "$room.length >= 12",
      ".write": "$room.length >= 12"
    }
  }
}
```

   これは「12文字以上の合言葉をパスに含めた場合だけ読み書きできる」ルールです。トップ階層の一覧は誰にも読めません。
4. 「データ」タブ上部に表示されるURLをコピーしておく。
   例：`https://clinic-stock-xxxxx-default-rtdb.asia-southeast1.firebasedatabase.app`
   （**末尾にスラッシュは付けない**）

## 2. 手元で動かす（任意・確認用）

Node.js（v18以上）が入っている前提です。

```powershell
cd C:\Users\key\Downloads\clinic-stock
copy .env.example .env
notepad .env        # VITE_FIREBASE_URL= の右側を、手順1-4のURLに書き換えて保存
npm install
npm run dev
```

表示されたURL（例：http://localhost:5173）をブラウザで開き、合言葉を入力して画面が出れば成功です。

## 3. GitHub（新規リポジトリ）

1. GitHubで新しいリポジトリを作る（例：`clinic-stock`、Private推奨）。READMEなどは追加しない。
2. PowerShellで次を実行（`<ユーザー名>` は自分のGitHub名）。

```powershell
cd C:\Users\key\Downloads\clinic-stock
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/clinic-stock.git
git push -u origin main
```

`.env` は `.gitignore` に入っているので、GitHubには上がりません（URLは次のVercelで設定します）。

## 4. Vercel（新規プロジェクト）

1. Vercelで「Add New → Project」→ 手順3のリポジトリを選んで Import。
2. 設定：
   - Framework Preset：`Vite`（自動で選ばれる）
   - Root Directory：**空欄のまま**
   - **Environment Variables**：名前 `VITE_FIREBASE_URL`、値 手順1-4のURL
3. 「Deploy」。完了したらURLが発行される。これがクリニックで使うURL。

> 環境変数を後から変えた場合は、Deployments から「Redeploy」が必要です。

## 5. 初回データの投入

1. 公開URLを開き、**合言葉を決めて入力**（12文字以上。例：クリニック名＋数字など、推測されにくいもの）。
   ここで決めた合言葉が、データの保管場所になります。**全端末で同じ合言葉を使います。**
2. 「設定」タブの「template.xlsx」をダウンロードし、入稿用Excelを作る。
   - 「書き方」シートに記入ルールがあります。
   - 「サンプル」と書かれた行は消してから使う。
   - 薬剤マスタ：品名、カテゴリ、数える単位、1箱の入数、未開封（箱）、バラ、最低在庫、補充目標、主な卸、備考（現在庫は自動計算）
   - 発送プラン：プラン名、大メニュー、セット名、月数、品名、数量、数量の単位（1行＝1プラン×1薬剤）
3. 「設定」タブ →「薬剤＋在庫＋プランを全置換（初回）」を選び、Excelを選択。
   - 赤い「修正が必要です」が出たら、行番号を見てExcelを直し、もう一度選び直す。
   - 緑〜黄色の「確認」は、取り込みは可能という意味（例：最低在庫が空欄の薬剤）。
4. 「この内容で取り込む」。完了したら「在庫」タブと「発送」タブを確認する。
5. 画面上部の **担当者** に名前を入れる（端末ごとに記憶されます。記録系の操作には必須です）。

## 6. 日々の運用

| やりたいこと | 操作 |
|---|---|
| 発送する | 発送タブ → プラン → 詰めて → 発送先・配送番号を入力 → 出庫を記録する |
| セット数が複数 | プラン画面の「セット数」を増やす（個数が自動で倍になる） |
| 卸から入荷した | 在庫タブ → 該当薬剤の「詳細・出納」→「卸から入庫」→ 箱とバラを入力 |
| 発注した | 在庫タブ「発注が必要」→ 発注数を調整 →「発注済にする」 |
| 発注分が届いた | 在庫タブ「発注済」→「入荷にする」（発注数がそのまま入庫される） |
| 実際の入荷数が違った | 「入荷にする」は使わず、「取消」→ 詳細・出納から実数で「入庫」 |
| 記録を間違えた | 詳細・出納の履歴で「取り消す」（在庫も元に戻る） |
| 新しい端末で使う | 公開URLを開き、同じ合言葉を入力する |
| プランを追加・変更 | Excelを直し、設定タブ「発送プランだけ更新」で取り込む（在庫・履歴はそのまま） |
| 棚卸しをやり直す | Excelの未開封・バラを更新し、「全置換」で取り込む（**履歴は消える**。先にバックアップを書き出す） |
| バックアップ | 設定タブ「Excelに書き出す」。書き出した薬剤マスタ・発送プランは、そのまま再取り込みできる |

## 7. 注意点（正直に）

- **合言葉は「鍵」ではなく「推測されにくいアドレス」です。** URLと合言葉を知っている人は誰でも読み書きできます。退職者が出たときなどは、合言葉を変える（＝新しいデータで作り直す）運用が必要です。厳密な権限管理が必要になったら、クリニックのサーバーに移して認証を付けるタイミングです。
- **発送先・配送番号の欄に、患者の氏名や住所を書かないでください。** 配送番号や管理番号だけにするのが安全です。
- 保存のたびに「最新を読み直してから書く」ので、複数人が同時に操作しても古い画面で上書きはされません。ただし、完全な同時操作（ほぼ同じ秒）では、あとの人が「失敗しました」と表示されることがあります。その場合はもう一度押してください。
- 画面は30秒ごと、およびタブを開き直したときに自動で最新になります。
- 合言葉を変えると別のデータ置き場になります（古いデータは残ります）。

## 8. うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 「設定が必要です」と出る | Vercelの環境変数 `VITE_FIREBASE_URL` が未設定。設定して Redeploy |
| 「読み込みエラー 401」 | Firebaseのルールが違う、または合言葉が12文字未満。手順1-3を再確認 |
| 「読み込みエラー 404」 | URLの誤り（末尾のスラッシュ、プロジェクト名違い）。手順1-4を再確認 |
| 画面が空のまま | 合言葉が違う（別のデータ置き場を見ている）。「設定」→「合言葉を入力し直す」 |
| Excelが取り込めない | `.xlsx` 形式か確認。シート名に「薬剤」「発送」を含める。列見出しを変えない |
| 「品名が薬剤マスタにありません」 | 発送プランの品名と薬剤マスタの品名が違う。コピーして貼る（スペースの全角半角は無視されます） |
| Vercelのビルドが失敗 | Root Directory が空か確認。ログの最初のエラー行を確認 |
